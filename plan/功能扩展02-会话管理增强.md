# 功能扩展 02 · 会话管理增强——重命名 / 归档 / 跨会话续接

> 配套《后端实施方案.md》与《前端实施计划.md》。对现有会话模块（`ConversationController` GET/POST/DELETE）的增强。
>
> 涉及：`d:\Corpedia\backend\` + `d:\Corpedia\frontend\`。目标：①支持会话重命名；②支持归档（列表隐藏、可恢复）；③支持「跨会话续接」——以某会话为源复制一份新会话继续提问。

---

## 一、现状与缺口（已核实）

- `conversation` 表：`user_id / title / department_id / status(1正常/0关闭) / created_at / updated_at`。`status` 目前只在 new 时置 1，**0 从未被写入**（可安全复用为「已归档」）。
- `ConversationController`：仅 `GET /api/conversations`、`POST /api/conversations`、`DELETE /api/conversations/{id}`、`GET /api/conversations/{id}/messages`。**无重命名、无归档、无复制**。
- 多轮历史：`RagChatService.loadHistory(conversationId)` 按会话 id 取最近 N 条（`history-messages=6`）拼入 Prompt。**只要新会话里复制了历史消息，续接即在 RAG 层自然生效**（无需改 RAG）。
- 前端 `ConversationList.vue`：仅「新建 / 切换 / 删除」；`ChatView.vue` 顶部 title 只读展示。

---

## 二、方案设计

### 2.1 数据模型

不新增表。**复用 `conversation.status` 表达归档**：

- `status = 1`：正常（active）
- `status = 0`：已归档（archived）——仅从默认列表隐藏，消息不删、仍可访问与续聊

> 决策：若后续要「置顶/多态」，再拆 `pinned tinyint` 或状态枚举；本期不引入，避免过度设计。

### 2.2 接口设计

| 方法 | 路径 | 说明 |
|---|---|---|
| PUT | `/api/conversations/{id}` | 重命名（body `{ title }`）；扩展支持 `modelId/kbIds`（功能04 复用） |
| PUT | `/api/conversations/{id}/archive` | 归档/取消归档（body `{ archived: true|false }`） |
| GET | `/api/conversations?scope=active\|all\|archived` | 列表加筛选（默认 `active`） |
| POST | `/api/conversations/{id}/fork` | 以该会话为源复制出**新会话**（含历史消息）续接 |

全部走既有归属校验：`ConversationService.requireConversation(userId, id)`（非本人 404/403）。

**约定**：
- 对已归档会话发消息：允许（`requireConversation` 不拦截），并在发消息成功时**自动把会话置回 active**（用户主动回访即视为恢复）→ `MessageService.ask` 里若 `status==0` 先置 1。
- `DELETE` 仍为硬删（级联清消息），归档≠删除。

### 2.3 `POST /conversations/{id}/fork`（跨会话续接）

- 请求：`{ "title": "..." }`（可空，默认 `原标题 的续接`）
- 行为：事务内
  1. 校验源会话归属；
  2. 新建 `conversation`（同 user/department，title=请求或默认，status=1）；
  3. 复制源会话全部消息 → 新 `conversation_id`（保留 `role/content/sources/similarity/answered/response_ms/created_at`）；
  4. 事务提交，返回新 `ConversationVO`。
- 效果：新会话拥有完整历史 → 用户继续提问时 `loadHistory` 自动带入上下文，实现「带着旧会话上下文开新会话」。

> 备选（本期不做）：跨**用户**续接（把别人的会话复制给自己）——涉及权限/敏感历史扩散，默认拒绝，仅本人 fork。

## 三、后端改造

### 3.1 `ConversationController`

新增端点：

```java
@PutMapping("/{id}")                        // rename
Result<ConversationVO> update(@PathVariable Long id, @RequestBody(required=false) ConversationUpdateRequest req)
@PutMapping("/{id}/archive")                // set archived
Result<Void> archive(@PathVariable Long id, @RequestBody SetArchiveRequest req)
@GetMapping                                  // scope 过滤
Result<List<ConversationVO>> list(@RequestParam(defaultValue="active") String scope)
@PostMapping("/{id}/fork")                   // 跨会话续接
Result<ConversationVO> fork(@PathVariable Long id, @RequestBody(required=false) ConversationForkRequest req)
```

DTO（`dto/request` 新增）：`ConversationUpdateRequest{String title; String modelId; List<Long> kbIds}`（modelId/kbIds 见功能04，本期先留字段）、`SetArchiveRequest{boolean archived}`、`ConversationForkRequest{String title}`。

### 3.2 `ConversationService`

```java
public ConversationVO update(Long userId, Long id, ConversationUpdateRequest req);  // 归属校验+改 title/覆盖会话元数据
public void setArchived(Long userId, Long id, boolean archived);                     // requireConversation + updateById(status)
public List<ConversationVO> list(Long userId, String scope);                         // status 过滤: active/archived/all
@Transactional
public ConversationVO fork(Long userId, Long sourceId, String title);                // 复制会话+消息
```
- `list`：`scope=active`→`status=1`；`archived`→`status=0`；`all`→不过滤。默认 active（前端默认 tab）。
- `update`：仅允许改 `title`（本期）与功能04 的 `modelId/kbIds`；不可改归属/部门。title 置空则回写首条问题或保持旧值。

### 3.3 `MessageService.ask`（归档自动恢复）

在 `requireConversation` 后判断：`conv.status==0` → `conv.setStatus(1); conversationMapper.updateById(conv);` 再继续走提问逻辑。

### 3.4 DDL

**无新列**（status 复用）。如需给功能04 预留，可在本阶段一并（见功能04）加 `conversation.model_id / kb_ids`。

## 四、前端改造

### 4.1 `api/conversation.ts`

```ts
export type ConvScope = 'active' | 'all' | 'archived'
export function updateConversation(id: number, data: Partial<{ title: string; modelId?: string; kbIds?: number[] }>) {
  return http.put<Conversation>(`/conversations/${id}`, data)
}
export function setConversationArchived(id: number, archived: boolean) {
  return http.put<void>(`/conversations/${id}/archive`, { archived })
}
export function listConversations(scope: ConvScope = 'active') {
  return http.get<Conversation[]>('/conversations', { params: { scope } })
}
export function forkConversation(id: number, title?: string) {
  return http.post<Conversation>(`/conversations/${id}/fork`, title ? { title } : {})
}
```

### 4.2 `ConversationList.vue`

- hover 显示三个操作图标：**重命名（inline 输入或弹窗）**、**续接**、**归档**；保留现有删除。
- 顶部加 **scope 切换**（`全部 / 进行中 / 已归档`，`el-radio-group` 或 Tab），切换即调 `listConversations(scope)`。
- 事件：`emit('rename', id, title)`、`emit('fork', id)`、`emit('archive', id, archived)`。
- 已归档项加灰/标签「已归档」。

### 4.3 `ChatView.vue`

- 顶部标题：点击进入 inline 重命名（输入框 + 回车/失焦保存 → `updateConversation(id,{title})` → 刷新列表）。
- 顶栏操作按钮：「归档本会话」（当前会话 `setArchived(id,true)` → 从列表移除/切到下一会话）。
- `fork` 处理：调 `forkConversation(id)` → 新会话 `unshift` 到列表并 `currentId` 切换到它（等同新开一个带历史的会话，可直接续问）。
- 默认加载 `listConversations('active')`；scope 由 `ConversationList` 状态决定。

## 五、验收

1. 重命名：会话标题可点击改名，列表与顶栏即时更新，刷新持久。
2. 归档：会话归档后不出现在「进行中」，切到「已归档」可见且灰显；回访（发消息）自动恢复 active。
3. 跨会话续接：对会话 A 点「续接」→ 生成新会话 B（含 A 的全部历史），在 B 中追问「那报销时限？」能正确带上 A 的上文指代回答。
4. 越权：他人会话不可重命名/归档/续接（归属校验 404/403）。
5. 删除仍为硬删，归档≠删除。

---

## 六、风险与注意事项

| 风险 | 应对 |
|---|---|
| 复用 `status` 语义改动 | `0` 现仅是「可归档」占位，未使用过；铭感清单：所有 `status=1 正常/0 关闭` 注释同步为「1 正常/0 已归档」 |
| fork 复制全部消息体量大 | 单会话消息量有限，一次性 insert 批量即可；如过大可只复制近 N 条（后续评估） |
| 续接越权扩散 | 仅本人 fork；跨用户续接默认拒绝 |
| 前端 scope 与「自动恢复 active」联动 | 归档会话发消息后切回 active，前端下次拉 active 列表即回显 |

> 后续可扩展：会话置顶/pinned、批量归档、把存档导出。
